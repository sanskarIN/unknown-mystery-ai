# Post-1.0 Maintenance Policy

> 🛒 Official publication: **https://ramsandesh.gumroad.com**

Version 1.0 establishes the stable public companion surface. Future maintenance should favor small backward-compatible improvements.

## Patch releases

Use patch releases for compatible bug fixes, documentation corrections, packaging fixes, test improvements, and security fixes that do not intentionally break the documented public API.

## Minor releases

Use minor releases for new backward-compatible utilities, examples, optional integrations, or documentation features.

## Major releases

Reserve major releases for intentional incompatible public API changes. Apply the deprecation policy first when practical.

## Maintenance priorities

1. Correctness and reproducibility.
2. Security and privacy boundaries.
3. Backward compatibility.
4. Clear learning value.
5. Cross-platform execution.
6. Small dependency surface.
7. Accurate licensing and commercial-publication boundaries.

## Release cadence

There is no requirement to release on a fixed schedule. Prefer evidence-backed releases over version churn.

The commercial publication can evolve independently from the companion package and is distributed through **https://ramsandesh.gumroad.com**.
